# sprint1

1.   目标:

     完成认证与 Todo 基础闭环,为后续 Finance,主题,Agent API 和 Dashboard 自定义提供稳定项目骨架.

2.   核心用户路径

     ```text
     用户打开项目
     → 完成注册或登录
     → 进入 Todo 工作区
     → 创建一条任务并设置基础属性
     → 修改任务状态或删除任务
     → 刷新页面后数据仍然正确保留
     ```

3.   功能范围

     -   认证: 注册,登录,登出,JWT cookie 和当前用户信息接口.
     -   Todo: 任务创建,列表,详情更新,完成状态和删除.
     -   前端壳层: 全局布局,鉴权状态,基础导航和移动端可用布局.
     -   后端基础设施: 数据库 session,迁移入口,路由注册,认证中间件和错误处理.
     -   文档: README 快速开始,认证文档,Todo 文档和 sprint 记录.

4.   验收清单

     -   未登录用户不能访问需要认证的数据接口.
     -   登录后可以创建和读取自己的任务.
     -   一个用户无法读取另一个用户的任务数据.
     -   前端页面能展示认证状态和 Todo 操作结果.
     -   后端测试覆盖认证和 Todo 关键路径.
     -   本轮变更已记录到 `changelog.md`.

## 范围与边界

1.   当前版本只做:

     -   认证和 Todo 的最小可用能力.
     -   保障前后端接口契约稳定.
     -   支持本地开发和基础自动化检查.

2.   当前版本不做:

     -   Finance 深度统计,预算和复杂图表.
     -   主题市场,脚本桥接和高级页面级 token 覆盖.
     -   Webhook,Agent SDK 和自动化规则.
     -   多租户团队协作.

## 技术边界

| 边界 | 当前选择 | 原因 |
| ---- | -------- | ---- |
| 登录态 | cookie-based JWT | 前端调用简单,便于浏览器会话管理 |
| API | RESTful JSON | 易于前端,测试和未来 Agent 调用 |
| 数据访问 | SQLAlchemy model + session | 保持后端数据访问集中且可测试 |
| 前端状态 | React Context + API client | Sprint 1 范围内足够轻量,避免提前引入复杂状态库 |

## 复杂度控制

为了避免过度设计,当前阶段遵守:

-   只抽象已经被认证和 Todo 同时复用的工具.
-   不在 Sprint 1 引入通用 Entity 系统的完整实现.
-   不为了未来插件系统提前改变当前路由和数据库结构.
-   所有新增行为必须能通过手动路径或测试验证.
