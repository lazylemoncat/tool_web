# 1_project_idea

## 1. 项目名称

Project Name: Tool Web

Repository Name: tool_web

一句话描述: 面向个人用户和 AI Agent 的 Web-first 个人信息管理平台,通过结构化数据,开放 API 和可自定义界面统一管理任务,记账和偏好配置.

## 2. 项目动机

我为什么想做这个项目?

-   我遇到的问题: 个人任务,财务记录,偏好配置和自动化入口分散在不同工具中,数据难以被统一检索和操作.
-   现有工具的不足: 很多工具只面向人工 UI 操作,缺少稳定结构化 API,不利于 AI Agent 或脚本安全读写个人数据.
-   我希望改善的体验: 用户可以在浏览器里完成日常管理,同时让 Agent 通过受控 API 执行查询,创建和更新操作.
-   这个项目对我个人的价值: 沉淀一个可长期扩展的个人工作空间,把 Todo,Finance,主题和未来日历,自动化能力统一到同一套数据与权限模型中.

## 3. 目标用户

| 用户类型 | 用户痛点 | 使用场景 |
| -------- | -------- | -------- |
| 我自己 | 需要集中管理任务,账本和日常数据,并希望后续接入 Agent 自动化 | 本地或私有服务器部署,日常使用 Todo 和 Finance,逐步扩展自动化 |
| 开发者 | 需要一个可二次开发,API 清晰,前后端职责明确的个人工具平台 | 在现有 Next.js + FastAPI 架构上增加模块,接口和 Agent 操作能力 |
| 普通用户 | 不想安装多个客户端,希望用浏览器跨设备访问个人工具 | 通过 PC,手机或平板访问响应式 Web 应用,管理任务和记账数据 |

## 4. 问题定义

这个项目真正解决的问题是:

-   为个人数据提供统一 Web 入口和模块化后端 API.
-   让 Todo,Finance,主题偏好等数据具备清晰的用户隔离,结构化模型和可测试接口.
-   为后续 Agent Token,Webhook,SDK 和自动化规则预留架构边界.

不解决的问题是:

-   MVP 阶段不做插件市场,复杂自动化,AI 对话 UI,多工作区和文件系统.
-   不以原生桌面端或移动端 App 为主线,坚持 Web-first.
-   不把富文本页面作为核心数据模型,优先维护结构化实体.

## 5. 竞品 / 替代方案

| 工具 / 方案 | 优点 | 缺点 | 我的差异点 |
| ----------- | ---- | ---- | ---------- |
| Notion | 灵活,生态成熟,适合文档和数据库混合管理 | Agent 写入受限,强依赖页面模型,自托管困难 | Tool Web 优先结构化 API,用户隔离和自部署 |
| Todoist | 任务体验成熟,多端同步稳定 | 主要聚焦任务,对财务和自定义工作流支持有限 | Tool Web 将任务,记账,主题和未来自动化放在同一平台 |
| 自建脚本和表格 | 简单直接,实现成本低 | 缺少统一认证,权限,前端体验和长期演进边界 | Tool Web 提供模块化前后端,测试和部署流程 |
