# Frontend Architecture

This document describes the current frontend structure after the Umi migration.

## Stack

- React 19
- TypeScript
- Umi 4
- Axios
- Radix UI
- dnd-kit
- Recharts

## Entry Points

| File | Purpose |
|---|---|
| `frontend/.umirc.ts` | Umi configuration: browser history, API proxy, and route tree. |
| `frontend/src/app.tsx` | Umi runtime entry: global providers, error boundary, toast providers, tooltip provider, and theme bridge setup. |
| `frontend/src/layouts/index.tsx` | Global application layout: session gate, i18n provider, theme provider, custom theme loading, top bar, and page theme synchronization. |
| `frontend/src/utils/pageTheme.ts` | Maps URL paths to custom-theme page keys such as `todo`, `finance`, and `settings`. |

The legacy Vite files `frontend/src/main.tsx`, `frontend/src/App.tsx`, `frontend/vite.config.ts`, and `frontend/index.html` are no longer used.

## Routing

Routes are configured in `frontend/.umirc.ts`.

Current route groups:

- `/` -> `HomePage`
- `/welcome` -> `LandingPage`
- `/todo` -> `TodoPage`
- `/settings/*` -> settings layout and sections
- `/finance/*` -> finance layout and child pages
- `/help` -> help page
- `/ui-preview` -> development UI component preview

Route hooks should be imported from `umi`:

```ts
import { useNavigate, useLocation, NavLink, Outlet, useSearchParams } from 'umi'
```

Do not import routing APIs directly from `react-router-dom`.

## Layout And Auth

`frontend/src/layouts/index.tsx` owns the application shell:

1. Reads session state from `AuthContext`.
2. Initializes the base theme from user preferences.
3. Loads the active custom theme when `custom_theme_id` exists.
4. Syncs the current route to `themeEngine.switchPage(pageKey)`.
5. Shows `AuthPage` when there is no authenticated session.
6. Shows `AppTopBar` and the active route outlet after login.

`/ui-preview` stays accessible in development mode without login so UI components can be checked quickly.

## Theme Runtime

The theme runtime has two layers:

- `theme.ts`: built-in mode switching (`light`, `dark`, `matcha`, `system`).
- `themeEngine.ts`: uploaded JSON theme runtime, CSS variable injection, custom button actions, and page-level overrides.

`frontend/src/app.tsx` installs `window.toolweb` through `themeBridge`, then registers theme query and page-switch functions:

```ts
installThemeBridge()
registerTheme({ getActiveConfig, getCurrentPage, switchPage })
```

Page-level theme keys are generated by `getThemePageFromPath()` in `frontend/src/utils/pageTheme.ts`.

## Development

Install dependencies first:

```bash
cd frontend
npm install
```

Start the frontend:

```bash
npm run dev
```

Build:

```bash
npm run build
```

The frontend now depends on `umi`. If `node_modules` still contains the old Vite-only dependency set, TypeScript checks will fail until `npm install` refreshes dependencies.

## Open Design Preview Entries

Open Design cannot execute Umi `.tsx` route modules directly as standalone preview artifacts. The finance pages therefore include thin preview wrappers under `frontend/public/open-design/`:

| File | Embedded route |
|---|---|
| `frontend/public/open-design/finance-dashboard.html` | `http://localhost:8003/#/finance/dashboard` |
| `frontend/public/open-design/finance-transactions.html` | `http://localhost:8003/#/finance/transactions` |
| `frontend/public/open-design/finance-budgets.html` | `http://localhost:8003/#/finance/budgets` |
| `frontend/public/open-design/finance-events.html` | `http://localhost:8003/#/finance/events` |

Finance child pages include dashboard, transactions, budgets, events, and manage. The manage page owns finance category and tag administration so the dashboard remains display-focused.

Start the frontend dev server before opening these files in Open Design. Source edits remain in `frontend/src/pages/finance/` and `frontend/src/components/finance/`; the wrappers are preview-only tooling.

## Migration Notes

The migration intentionally does not preserve Vite compatibility. The project is still in active development, so the frontend now uses Umi conventions directly:

- Umi owns route creation.
- `src/app.tsx` owns runtime providers.
- `src/layouts/index.tsx` owns authenticated shell layout.
- TODO page state moved from the old app root into `src/pages/TodoPage.tsx`.
- Route imports were changed from `react-router-dom` to `umi`.

## UX Notes

- The todo sidebar only contains todo folder navigation and shared shell actions. Finance entry points live in the home/finance routes instead of inside the todo folder list.
- `ConfirmDialogProvider` uses the shared `Modal` component. Delete confirmations should pass a clear `description`; `Modal` omits the body section when no children are provided so confirm dialogs do not show an empty middle area.
